# STYLE.md — Правила проектирования API

Ниже приведены 10 правил, соблюдаемых при разработке контракта Library API.

1. **Версионирование в пути** — все эндпоинты начинаются с префикса `/v1/`, указанного в `servers`. При внесении несовместимых изменений создаётся новая версия (`/v2/`), старая поддерживается в течение периода устаревания.

2. **kebab-case в путях, snake_case в JSON** — сегменты URL и имена query-параметров пишутся через дефис (`/books`, `full_name`), а поля в телах запросов и ответах — в `snake_case` (`book_id`, `loaned_at`, `available_copies`).

3. **Ресурсы существительные, операции — HTTP-методами** — Коллекции именуются во множественном числе (`/books`, `/readers`, `/loans`), CRUD соответствует GET/POST/PUT/DELETE, а специфичные действия выносятся в подкатегории (`POST /loans/{id}/return`).

4. **Единый формат ошибок** — все ошибки возвращают объект `ErrorResponse` с полем `error.code` из строго заданного перечисления (`INVALID_REQUEST`, `NOT_FOUND`, `VALIDATION_ERROR`, `CONFLICT`, `BUSINESS_RULE_VIOLATION`, `IDEMPOTENCY_MISMATCH`) и понятным `message`.

5. **Осмысленные HTTP-коды** — используется 200 для успешного GET/PUT, 201 для создания, 204 для удаления, 400 для неверного запроса, 404 при отсутствии ресурса, 409 при конфликте, 422 при ошибке валидации или бизнес-правила, 500 при внутренней ошибке сервера.

6. **Read-only серверные поля** — поля, вычисляемые сервером (`id`, `available_copies`, `loaned_at`, `returned_at`, `registered_at`), помечаются `readOnly: true` и не принимаются от клиента. Запрещены неизвестные поля в запросах (`additionalProperties: false`).

7. **Пагинация, фильтрация, сортировка** — все коллекционные эндпоинты поддерживают `page` и `limit`, фильтрацию по соответствующим полям resource, сортировку через параметр `sort` (например, `?sort=published_year,-title`).

8. **Идемпотентность на изменяющих операциях** — `POST /loans` поддерживает заголовок `Idempotency-Key`: при повторном запросе с тем же ключом возвращается полный replay ответа, при разном теле — ошибка `IDEMPOTENCY_MISMATCH`, срок хранения ключа — 24 часа.

9. **Документирование на уровне спецификации** — каждая операция имеет `summary`, ключевые операции имеют `description`, у каждой коллекции и сценария ошибок есть минимум 3 `examples` (включая пример ошибки).

10. **Явные теги и группировка** — все операции помечены тегами `Books`, `Readers`, `Loans`, что позволяет генераторам документации и клиентов структурировать API по ресурсам.
